### 2.1 Industrial Dual-Engine Architecture
Edge mobile LLMs can encounter thermal throttling, context boundary truncation, or invalid JSON syntax under heavy workloads. The Learning Companion guarantees 100% uptime through a **Dual-Engine Architecture**:
1. **Primary Generator (Llama 3.2 1B INT4)**: Generates highly customized weekly topics, personalized practice assignments, and contextual milestones.
2. **Pedagogical Graph Validator**: Validates JSON syntax, schema completeness, daily time allocations, and prerequisite consistency against strict domain DAGs.
3. **Deterministic Expert Fallback**: If an LLM call exceeds maximum retries, encounters a syntax error, or is manually skipped by the user tapping "Use Instant Fallback", the deterministic template instantly populates the weekly curriculum from curated pedagogical data without breaking user experience.

### 3.2 Performance Compliance Analysis
1. **Generation Speed Compliance**:
   - The PS4 competition guideline targets $\ge 22$ tokens/sec on Arm hardware.
   - On standard single-node roadmaps (Trial 1: **22.61 tok/s**) and remedial revision generation (Trial 3: **23.75 tok/s**), the model comfortably exceeds 22 tokens/sec.
   - On dense multi-node prompts (Trial 2: **16.93 tok/s**) and Indic script prompts (Trial 4: **18.72 tok/s**, Trial 5: **18.00 tok/s**), throughput drops below 22 tokens/sec due to larger prefill KV-cache overhead and subword byte-fallback fragmentation.
   - Across the five representative on-device trials, the overall mean decode throughput is **20.00 tokens/sec**, with **2 out of 5 trials exceeding 22 tokens/sec**.
   - Compliance Status: **Partially Compliant / Conditional** (Workload-dependent: fully compliant on standard curriculum tasks, averaging 20.00 tok/s across complex heterogeneous workloads).

2. **RAM Footprint Metric Accounting (MiB vs GiB vs MB vs GB)**:
   Android's low-level memory reporting via `Debug.MemoryInfo.totalPss` natively operates in kibibytes ($1\text{ KiB} = 1,024\text{ bytes}$). Converted across standard accounting definitions:
   - **Proportional Set Size (PSS)**:
     - Measures private physical pages plus the proportional share of shared libraries.
     - Observed Range: 1,549.2 MiB – 1,560.1 MiB (Mean: **1,554.5 MiB**).
     - In Binary IEC Units: $1,554.5 / 1024 = \mathbf{1.518\text{ GiB}} \approx \mathbf{1.52\text{ GiB}}$.
     - In Decimal SI Units: $1,554.5 \times 1,024^2 / 10^9 = \mathbf{1.630\text{ GB}}$ ($1,630.0\text{ MB}$).
     - Margin to 1.8 GB Limit:
       - Binary $1.8\text{ GiB}$ ($1,843.2\text{ MiB}$): **288.7 MiB safety margin**.
       - Decimal $1.80\text{ GB}$ ($1,800.0\text{ MB}$): **170.0 MB safety margin**.
     - Verdict: **COMPLIANT** (Strictly $< 1.8$ GB under both binary and decimal accounting).
   - **Resident Set Size (RSS)**:
     - Measures all physical pages currently mapped to the process address space.
     - Observed Range: 1,068.7 MiB – 1,551.6 MiB (1.04 – 1.52 GiB / 1.12 – 1.63 GB).
     - Margin to 1.8 GB Limit: **291.6 MiB** safety margin even at peak RSS.
     - Verdict: **COMPLIANT** (Strictly $< 1.8$ GB).
   - **Peak Virtual High Water Mark (`VmHWM`)**:
     - Tracks peak resident pages recorded by the Linux kernel since process creation, including transient pages touched during initial `mmap` faulting of the 1.06 GB weights file.
     - Observed Range: 1,827.9 MiB – 1,923.3 MiB (1.78 – 1.88 GiB / 1.91 – 2.01 GB).
     - Verdict: **CONDITIONAL / EXCEEDED** if peak transient `VmHWM` is treated as the official accounting metric.

3. **Latency & Time to First Token (TTFT)**:
   - Cold initialization (loading weights from flash into memory map): **4.2 – 5.2 s**.
   - Warm TTFT for standard English prompts: **366 – 408 ms** (near instantaneous).
   - Indic script prompts: **794 – 1,241 ms** due to multi-byte token expansion during prompt prefill.

## 6. Qualcomm Hexagon NPU (QNN HTP) Status & Future Roadmap

Extensive physical testing was conducted on the Qualcomm Hexagon Tensor Processor (HTP) on the Snapdragon 7+ Gen 3 (`SM7675`):
- **Hardware Architecture**: Verified `SM7675` contains Hexagon HTP **Architecture V73** (4 hardware threads).
- **FastRPC Communication**: Verified `libcdsprpc.so` and `libQnnHtp.so` initialize, open `adsprpc-smd`, spawn FastRPC threads on CPU Core 7 (Cortex-X4), and establish contact with the Hexagon cDSP.
- **Hardware Rejection of Mismatched Bytecode**: A test QNN model compiled for HTP V75 (SM8650) was rejected by the cDSP runtime with error `0x138d (Request feature arch with value 75 unsupported)`. This provided definitive hardware proof that the runtime executes on the real Hexagon DSP without silent CPU fallback.
- **Isolation Decision**: Because ExecuTorch 0.7.0's QNN Flatbuffer schema is in active development and pre-compiled V73 Llama 3.2 binaries require specialized Linux compilation pipelines, the QNN implementation has been safely preserved in the `qnn070` flavor, ensuring the production `prod060` app remains rock-solid for Phase 1 submission.
